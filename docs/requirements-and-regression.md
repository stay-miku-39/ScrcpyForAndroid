# Scrcpy Android 功能需求、验收与重构约束

版本基线：0.8.0；整理日期：2026-10-22。本文描述当前实现及验收方法，供实体机测试、后续回归和项目重构使用。实际执行记录见根目录 [TESTING.md](../TESTING.md)，麦克风/摄像头调查见 [INPUT_SHARING.md](../INPUT_SHARING.md)。标记为待实体机验证的项目不能视为已经兼容所有厂商系统。

## 1. 产品与环境

- 主控是普通 Android APK，最低 Android 11 / API 30，targetSdk 36（Android 16）。主要使用场景是 Android 16 主控控制 Android 15/16 设备。
- 被控端通过 ADB 启动 scrcpy shell 服务；一般远控不要求安装主控 APK、root 或无障碍服务。测试探针只属于测试 APK。
- 根目录存放迁移代码；`scrcpy/` 是独立 Git 子模块，固定 5.0.1 / `a60891aea193d92e7e5c3942700eca63f9d19a5f`，本次未修改上游。
- 构建使用 JDK 21 或以上、Gradle Wrapper 和 Android SDK API 36；默认 compileSdk / targetSdk 均为 36。
- 设备集成验证需要明确指定的主控与被控测试设备；序列号、IP、配对端口和连接端口均从当次设备读取，不能复用文档中的固定现场配置。

## 2. 导航与状态

| 编号 | 需求 / 当前行为 | 验收要点 |
| --- | --- | --- |
| NAV-01 | 三个一级入口：连接、设备与凭据、工具 | 切换不修改密钥、不主动断开 ADB |
| NAV-02 | 无线配对、凭据详情、扫描、Shell、文件、设置为二级页面 | 返回回到所属一级页；设置回到连接页 |
| NAV-03 | 右上角更多菜单提供设置、凭据、设备管理和日志导出 | 设置从真实菜单可进入，页面可滚动 |
| NAV-04 | 已连接时右下角显示一键远程控制按钮 | 任意页面可启动；断开时隐藏；执行操作时不重复启动 |
| NAV-05 | 设备页统一查看当前连接、保存记录及启动/关闭小窗 | 本地列表、ADB 授权和运行会话是不同状态 |
| NAV-06 | 全屏主要交互是可拖动悬浮球，点击展开菜单 | 方向变化后球仍在可见安全区域，菜单关闭后可再次展开 |
| NAV-07 | 整个设置页显式保存；离开丢弃草稿，进入读取已保存配置 | 后台、外观、诊断和音视频均须点击底部“保存全部设置”；未保存不能影响活跃窗口；切后台也丢弃；保存只写修改的 UI 偏好，不覆盖并发更新的窗口几何 |

连接状态至少区分：未连接、正在操作、ADB 已连接、全屏会话、小窗会话、会话结束但 ADB 保留。界面阻塞操作必须在后台执行并可取消。发生错误应显示可读状态并记录异常阶段。

## 3. ADB、身份与设备记录

| 编号 | 需求 / 当前行为 | 验收要点 |
| --- | --- | --- |
| ADB-01 | 输入 IP 与端口执行传统 TCP ADB 连接、RSA 授权、重连和断开 | Shell 返回真实被控输出，拒绝授权/错误端口有明确失败 |
| ADB-02 | Android 无线调试支持六位配对码、配对端口及 TLS 连接 | 正确 PIN 成功，错误 PIN 拒绝；连接端口与配对端口不能混用 |
| ADB-03 | RSA 身份以 Android Keystore AES-GCM 加密，保存在不备份目录 | 重启/覆盖安装后指纹不变，配对码不落盘 |
| ADB-04 | 保存最近 IP、连接端口、配对标记，允许别名、修改端口及删除本地记录 | 删除记录不删除密钥，也不替代被控端撤销授权 |
| ADB-05 | USB Host 枚举 OTG 设备及 ADB 接口，处理 USB 与 ADB 两次授权 | 真机确认线材、供电、首次授权、拒绝及拔线；USB/TCP 使用同一身份 |
| ADB-06 | 在当前 USB 连接上请求 TCP 5555，再输入 Wi-Fi IP 重连 | 不假定 USB 设备有固定 WLAN 地址；需实体机验证 |
| ADB-07 | ADB 流可供音视频、控制、方向查询及麦克风并发使用 | 流 ID 唯一，快速无输出 Shell 的正常 EOF 不误报拒绝；真实拒绝仍报错 |

不实现自动重连；被控撤销授权、主控卸载/清除数据后需重新授权/配对。日志不输出私钥、PIN 或剪贴板正文。端口改变通常无需重建身份。

## 4. 视频、声音、触控与剪贴板

| 编号 | 需求 / 当前行为 | 验收要点 |
| --- | --- | --- |
| REM-01 | 每次启动上传当前子模块构建的 scrcpy 服务端，退出清理；连接中分别显示各阶段 | 区分上传、能力检查、显示查询/应用、服务准备/启动、通道/握手、解码初始化、首帧等；开启日志后按 trace 记录耗时和安全参数；失败也回收资源 |
| REM-02 | H.264 / MediaCodec / SurfaceView 显示，默认最大边 1600、60 fps、目标 8 Mbps / 软上限 20 Mbps | 持续解码，旋转后收到新尺寸及有效画面，无拉伸 |
| REM-03 | 多点触控按视频实际尺寸映射，保持 pointer ID | 双指 DOWN/MOVE/UP 实际到达被控端；松手、退出及切换时释放触点 |
| REM-04 | 返回、主页、最近任务、音量和远端旋转操作 | 动作发生在被控端，全屏退出由菜单明确执行 |
| REM-05 | 全屏音量实体键默认同步，可关闭 | 按下、重复、松开都转发；开启时本机媒体音量不变；离开时补发松开 |
| REM-06 | 被控声音以 48 kHz 双声道 PCM16 播放，可在连接前关闭 | 播放字节持续增加且非静音；全屏/小窗切换后继续 |
| REM-07 | 全屏前台双向纯文本剪贴板、去重、获取和粘贴 | 中英文双向内容一致，自动同步可关闭；后台/小窗不读本机剪贴板 |
| REM-08 | 媒体通过文件传输共享 | 图片/视频 MIME 剪贴板自动同步尚未实现 |
| REM-09 | 控制队列最多 64 条、总负载 512 KiB；普通待发送操作有效期 250 ms，触控 UP 不过期，队满优先淘汰 MOVE | 等待 ADB WRTE 许可后检查有效期；同一连续 MOVE 段按触点合并，不跨任何输入边界；一次写入最多合并 16 个连续 MOVE；满队列不结束会话 |
| REM-10 | 过期 MOVE/未发送 DOWN 不再释放其他长按；触控 UP 按顺序保留；按键过期或关键边界严重溢出仍安全释放 | 丢弃孤立 MOVE/重复按键/UP；组合键单次写入、逆序释放；分别抬指不能取消其他指；pointer ID 复用有序；离开明确释放、关闭不重放旧操作 |
| REM-11 | 解码输出积压时丢弃旧的已解码帧，只显示当前最新可用输出 | 每轮最多丢 32 帧后显示一帧，单独的最后一帧立即显示；不随意丢弃 H.264 压缩参考帧，不改变服务端协议/默认码率 |

剪贴板数据上限约 256 KiB；超限不发送。DRM 画面、禁止捕获的音源、厂商输入注入权限均受被控系统限制。声音尚无独立时钟漂移补偿和精确音画校准。

弱网策略优先减少尚未发送的旧操作和解码后的显示积压，不承诺 250 ms 的远端执行延迟。已经进入 TCP/USB 写入或开始分块发送的消息必须完成协议帧，不能中途截断。TCP 重传、编码端或传输缓冲中的压缩视频积压仍可能增加延迟；持续带宽不足时仍需后续码率自适应等工作。安全释放在通道恢复可写后执行，真实断线仍按原逻辑结束会话。

## 4.1 分辨率与音视频设置（0.6.0-dev）

入口：现有设置页的“分辨率与音视频”。配置全局共享，点击保存后只作用于新建的 ScrcpySession。关闭该设备投屏再打开即可生效，不要求断开 ADB；已有全屏、小窗、后台会话、输出交接及方向变化均继续使用启动快照。

| 编号 | 需求 / 当前行为 | 验收要点 |
| --- | --- | --- |
| STREAM-01 | 原有逻辑尺寸、本地主控屏幕自然方向尺寸、本机比例短边 720/1080/1440、固定 720×1280/1080×1920/1440×2560、自定义宽高 | 自定义每边 128–8192 px；本机比例档位按 8 px 取整；本机尺寸按新会话启动时读取，不连续跟随窗口 |
| STREAM-02 | 用户选择优先修改被控主屏，或优先独立虚拟显示 | 原有尺寸也遵循路线偏好；虚拟显示不是手机当前画面的副本，可显式指定启动包名，留空尝试系统桌面或设置 |
| STREAM-03 | 启动阶段优先路线失败，尝试另一条；两条均失败则原始主屏 | 有界尝试、记录和提示原因；成功建立后真实断线结束会话，不借此自动重连；用户保存的选项不因回退被改写 |
| STREAM-04 | 主屏覆盖先持久保存原有 override 或 reset，结束后恢复 | 已有 override 必须按原值恢复；窗口交接与后台不恢复；恢复失败保留端点记录，下次同端点新会话先恢复；旧会话延迟清理不得覆盖新会话 |
| STREAM-05 | 逻辑显示尺寸与视频传输最大边独立 | 默认最大边 1600，0 表示不限；编码器仍可按对齐/能力降尺寸；全屏和小窗继续等比居中完整显示，取容器能容纳的最大尺寸，不拉伸、不裁切 |
| STREAM-06 | 视频 H.264/H.265/AV1/VP8/VP9；目标/上限范围 100000–100000000 bit/s、最高帧率 1–240 | 默认 H.264、目标 8 Mbps / 软上限 20 Mbps、60 fps；本地解码器与远端编码器预检，保留输出追帧、Surface 交接及压缩参考链 |
| STREAM-07 | 音频 PCM/AAC/Opus/FLAC；码率 16000–512000 bit/s | 兼容默认 PCM，新安装可按能力初始化；48 kHz 双声道 PCM16 播放；压缩音频按配套协议解析；PCM 忽略码率和组件设置，FLAC 实际码率依内容而定 |
| STREAM-08 | 高级设置可指定被控音视频编码器和本地音视频解码器名称，留空自动 | 名称限 ASCII 组件字符，不拼接任意 Shell；组件/格式不可用或启动失败回退 H.264/PCM 并提示，最终音频失败仍尽量保留视频 |
| STREAM-09 | 异步读取本机硬件编解码目录，格式选项标注“本机硬解”，仅首次安装首次打开初始化推荐格式 | 优先可用 H.264 硬解及硬解 AAC/Opus，压缩音频可软件回退；组件名称保持自动；不覆盖升级/已有/手工设置，不因能力刷新丢草稿；本地硬解不代表远端硬编码支持 |
| STREAM-10 | 常用设置为软上限；高级目标可选默认、自动比例和自定义，另保留编码器 CBR 选项 | 默认目标 `min(8 Mbps,上限)`；自动 `max(0.1 Mbps,min(80%×上限,8 Mbps))`；自定义不能高于上限。旧目标保留在自定义字段，升级先用默认；显式保存，仅新会话生效；CBR 启动失败移除选项重试，仍保留软上限 |
| STREAM-11 | 自动模式优先尝试适合当前尺寸、声明低延迟能力的本机硬件解码器 | 创建/配置失败继续尝试并回到原自动选择；指定组件仍优先遵从；保留 goldfish Surface 交接回退和输出追帧；能力声明不等于已测出真机延迟改善 |
| STREAM-12 | 服务端按约 1 秒压缩输出窗口反馈调低编码目标，最低 0.1 Mbps；有余量后缓慢恢复且不超过初始目标 | 不延迟发包、不丢参考帧；首秒/关键帧可突发，不保证网络硬上限；拒绝动态更新或最低目标下持续超限时提示未生效。源码子模块保持固定，配套构建插入显式钩子且匹配失效即构建失败，协议不变；详见 [码率控制](bitrate-control.md) |

虚拟显示复用锁定的 scrcpy 5.0.1 `new_display`，本版不使用连续动态 resize；通过当前控制协议启动应用，默认请求虚拟显示结束时把任务移回主屏。可见桌面、应用是否允许多显示及任务迁移效果由 ROM/应用决定。方向监控选择当前虚拟 display ID，不能继续查询物理 display 0。主屏尺寸恢复依赖 ADB 可写；断网/强制停止时不承诺立即恢复，也不跨改变后的 IP/端口自动识别同一物理设备。

专项测试 APK 参数：`-e mediaCase main|virtual|fallback|presets|codecs|stages|quality|touchHold`（每次一个）；`touchHold` 的拥塞断言需配套测试代理注入控制 ACK 延迟，单独执行不算弱网验证。`-e featureCase draft|logging|codecDiscovery` 分别测试草稿、诊断开关和能力发现。原有基本回归可加 `-e defaultMedia true` 暂用默认音视频参数，结束恢复原快照。实际执行与模拟/真机边界见 TESTING.md。

## 4.2 可选质量参数（0.6.1-dev）

全屏悬浮球 → **质量参数** 二级菜单，提供总开关与逐项选择，选择即时全局保存。设置页手动保存规则不改变球菜单的即时开关。默认关闭；只统计选中项，后台、小窗、关闭/失去会话所有权时停采。恢复全屏继续相同会话并按已选项重新开始采样。

| 编号 | 项目与含义 | 验收要点 |
| --- | --- | --- |
| QLT-01 | 默认左上角、透明背景、字体可配置，普通显示不接收触摸 | 不阻挡底下远端应用；小窗没有此 View；适配安全边距；默认白色/100% |
| QLT-02 | 视频接收/解码/Surface 回调帧率，音视频有效载荷码率与媒体包速率 | 1 秒窗口；媒体包不等于网络 IP 包；Surface 回调不宣称屏幕实际光学刷新率 |
| QLT-03 | 视频输入缓冲等待、入解码队列至输出耗时；音频 feed 处理耗时/AudioTrack 缓冲与欠载 | PTS 映射仅视频延迟选中时建立；音频处理包含解码和输出等待，不等于单帧纯解码；远端编码耗时未上报则明确不可用 |
| QLT-04 | 控制 ADB 写入次数/字节速率、队列深度、排队与写入平均耗时 | 批写按实际 WRTE 计数；排队/写入分别测量；不称为远端消费率 |
| QLT-05 | ADB Shell 往返时间、实际编解码格式/组件和尺寸 | 往返探针仅选中时每 3 秒一次、单请求有界；包含 Shell 开销，不称为端到端延迟；未获得组件名称则显示未知 |
| QLT-06 | 统计工作随选项启停，切换输出按当前所有权处理 | 未选项不建计数/时间映射；FPS 监听线程和 RTT 流关闭后退出；不改正常解码/音频就绪必需的已有状态计数 |
| QLT-07 | 全屏质量菜单提供自定义位置，拖动时仍显示远端画面 | 仅定位模式拦截参数窗口的触摸，先释放远端输入；完成即时保存比例位置；取消/返回/切后台/切设备丢弃本次定位；横竖屏和文本尺寸变化后保持在安全可见区域；关闭统计/0% 字体仍可用临时预览定位且不启动统计 |
| QLT-08 | 字体颜色有 HSV 调色盘、明度、常用色块与预览，也保留颜色编码输入 | 调色盘取消不改草稿，确认只改草稿；整页保存后应用；离开丢弃；不改变单独的字体不透明度 |
| QLT-09 | 视频码率项显示初始目标、当前编码请求、软上限、实际有效载荷及生效模式；组件项说明低延迟能力 | 码率不含 ADB/IP/音频开销，当前请求来自服务端调节日志，不等于编码器保证值；限额失败显示未生效；能力不能写成端到端延迟；已报告组件名应在稍后开启质量菜单时显示 |

## 5. 电源与唤醒（0.4.0）

全屏路径：悬浮球 → **电源与唤醒**。电源功能使用现有 scrcpy 控制通道的键码注入，不切断 ADB，不修改被控端休眠策略。

| 编号 | 操作 | 注入及验收 |
| --- | --- | --- |
| PWR-01 | 唤醒屏幕 | KEYCODE_WAKEUP，约 80 ms；已熄屏时恢复亮屏，不自动解锁密码 |
| PWR-02 | 点按电源 | KEYCODE_POWER，约 80 ms；被控系统切换亮/熄屏 |
| PWR-03 | 长按电源 | KEYCODE_POWER，约 800 ms；实际结果由 ROM 的长按设置决定，可能是电源菜单或语音助手 |
| PWR-04 | 电源 + 音量− / 电源 + 音量+ | 同一控制写入中连续发送两键 DOWN，约 400 ms 后逆序 UP；用户只需点一次组合按钮 |
| PWR-05 | 小窗电源 | 顶部右侧 Material 电源矢量图标，点按约 80 ms，长按约 800 ms；没有额外操作菜单；内容描述与长按提示保留中文，不依赖字体是否包含电源字符 |
| PWR-06 | 释放保证 | 新动作先释放旧动作；暂停、退出、窗口切换和服务销毁释放；内部时长限制 50–1200 ms |

POWER + 音量− 在 Android 16 模拟器上以实际生成截图验收。POWER + 音量+ 的系统动作因 ROM 而异，协议序列通过单元测试，系统结果需实体机核对。无法通过软件电源键启动已经彻底关机的设备。

测试长按时临时把专用目标 `power_button_long_press` 设为 1，结束恢复。刚唤醒立即再次按 POWER 可能触发 Android 双击电源动作；专项测试按真实独立手势间隔执行。应用不自动改变这些系统设置。

## 5.1 多连接与后台（0.5.0）

| 编号 | 需求 / 当前行为 | 验收要点 |
| --- | --- | --- |
| MULTI-01 | 同时保留多个 TCP/TLS/USB ADB，每个端点各有连接、执行器和远控会话 | 连接、失败或断开 B 不影响 A；共用原 RSA 身份，覆盖安装不清数据 |
| MULTI-02 | 多个设备可各开一个小窗；同设备重复打开复用现有输出 | 两路持续解码，触控/电源/标题查询固定在各自目标；关闭单窗保留其 ADB |
| MULTI-03 | 全屏仅一个 Activity；选择另一设备复用全屏入口，结束旧全屏远控 | 不关闭其他设备的小窗；从小窗恢复使用同一 ScrcpySession |
| MULTI-04 | 右下角快捷按钮启动最新成功建立的 ADB 的远控 | 改变工具目标、打开旧设备远控不改变最新顺序；最新设备断开回退前一个仍在线连接 |
| MULTI-05 | 设备页分别选择工具目标、全屏、小窗、关闭远控和断开 ADB | Shell/文件明确当前工具目标；文件选择器回调固定到开始操作的设备 |
| BG-01 | 设置中“后台保留远程控制连接”默认开启 | 全屏离开前台转到后台 EGL 输出，原服务端/控制/媒体流继续；恢复时切回 Surface |
| BG-02 | “切换后台时，全屏自动转为小窗”独立保存，默认关闭 | 需后台保活和 overlay 授权；按 Home 后同会话交接；未授权时保留后台连接 |
| BG-03 | 单个 connectedDevice + mediaPlayback 前台服务管理所有连接/远控 | 常驻通知管理设备、停止全部远控、明确断开全部 ADB；会话活动时持有 partial wake lock，空闲释放 |
| BG-04 | 后台与小窗不读本机剪贴板、不转发实体音量键、不采集麦克风 | 暂停时释放触点/按键并停方向查询；回到全屏不会自动恢复麦克风 |
| BG-05 | 关闭后台保活后，离开全屏仍结束远控并保留 ADB | 显式小窗继续由前台服务维持；强制停止、断网、系统回收不承诺存活或自动重连 |

这里的“同时多个 ADB”以连接端点区分，不把同一物理设备的多个端口合并。多个视频解码器的上限由主控硬件决定。窗口沿用统一尺寸/位置偏好，新开窗口错开初始位置，后续可独立拖动/缩放。后台保活不包含系统电池优化白名单、开机自启或杀进程后重连。

专项入口：`-e multiDevice true -e host <目标A地址> -e port <目标A端口> -e secondHost <目标B地址> -e secondPort <目标B端口>`，由明确指定的第三台主控运行。两台目标需测试探针 APK；测试恢复偏好/历史并停止探针与会话。实际执行结果见 TESTING.md。

## 7. 原生自动旋转与通知栏（0.4.0）

- ROT-01：**默认开启**，全屏球菜单中的“自动屏幕旋转”可关闭并保存；关闭时请求方向为 UNSPECIFIED，恢复主控系统的方向策略。
- ROT-02：在后台调用被控显示服务 `cmd display get-displays`，只解析物理 display 0 的尺寸和 rotation 0/1/2/3；约每 1.2 秒查询，视频尺寸变化时主动刷新。读取超时 2 秒，响应上限 256 KiB；ADB 打开流另受连接库超时限制。
- ROT-03：根据远端方向和自然屏幕方向调用 Activity `setRequestedOrientation`，支持正/反横屏与正/反竖屏。通过系统窗口旋转处理动画、系统栏和触摸坐标，不调用画面 View 的旋转来冒充界面旋转。
- ROT-04：查询不可用时按视频宽高回退到横/竖屏；只有宽高比例时无法区分 0° 与 180°，也无法区分两个横屏方向。日志应注明 display service 或 video aspect 来源。
- ROT-05：旋转时关闭菜单、释放触点及按键；Activity 声明处理方向/尺寸配置变化，保持同一个会话。暂停、退出、小窗交接停止轮询，废弃上一轮 UI 回调。
- ROT-06：Android 16 大屏适配使用 Activity 的 restricted-resizability 兼容退出属性；将来提高 targetSdk 至 37 时必须重新评估大屏强制适配，不能直接继承兼容承诺。
- ROT-07：全屏菜单增加“通知栏 / 快捷设置 / 收起通知”，使用 scrcpy 5.0.1 类型 5/6/7 控制**被控端**面板。
- ROT-08：主控使用系统沉浸模式；边缘手势仍能临时唤出主控系统栏，普通应用不能可靠彻底禁用本机通知栏。远端专用按钮减少两端下滑冲突；不申请设备所有者或系统特权。

官方参考：[沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)、[Android 16 大屏与方向行为](https://developer.android.com/about/versions/16/behavior-changes-16#adaptive-layouts)。桌面模式、多窗口、折叠屏和厂商方向策略可能限制 Activity 请求，需实体机单独验收。

## 10. 重构时必须保留的边界

| 模块 / 文件 | 职责与约束 |
| --- | --- |
| MainActivity / MainUi | 连接操作与分级界面；不得在导航、设置中重建身份或阻塞 UI |
| Identity / AdbManager / RuntimeState / DeviceConnection | 持久身份、ADB 连接、后台执行器；ADB 生命周期长于单次投屏 |
| ScrcpySession / ControlProtocol / MediaPacket | 固定上游版本的握手、音视频与控制消息；协议编号/字段长度须对照子模块 |
| RemoteDisplay | Surface 所有权、等比布局、坐标换算和 pointer 释放；不混入设置页面逻辑 |
| RemoteActivity | 全屏球菜单、前台剪贴板、实体键、原生 UI 方向和麦克风生命周期 |
| RemoteKeyActions | 有界按住及组合键；每次 DOWN 必须有对应 UP，持有原会话以便正确释放 |
| FloatingWindowService / FloatingWindow / WindowGeometry / RemoteDeviceName | overlay、前台通知、圆角/等高栏、图标与拖动手柄、名称回退/宽度省略、屏幕约束及输出交接；不得重复启动服务端 |
| RemoteRotationMonitor / RemoteOrientation | 可取消后台显示查询、纯方向解析与比例回退；过期回调不能影响新界面 |
| UiPreferences | 透明度默认值及范围；与 devices/Identity 隔离；监听器须注销 |
| MicrophoneForwarder / src/inputServer | 主控采集与 shell 路由；独立可选通道；失败/撤销授权必须释放录音 |
| vendor/adb | 本地固定来源及改动记录；并发、流控、EOF、断线、USB 由独立回归覆盖 |

会话约束：每个设备的会话独立，任意时刻只有该设备的当前输出视图或后台 EGL 输出拥有会话；交接先挂接新 Surface 再销毁旧视图。旧 Activity / Service 销毁不能关闭已经转移的会话。关闭操作异步完成，丢弃未发送操作，控制写线程短暂尝试释放已发送的触点和按键。窗口/方向/透明度修改不重新配对、不重启 ADB、不重建音视频连接。

线程约束：View、PopupWindow、WindowManager 更新及键释放在主线程；网络、显示服务查询、传输和解码在后台。任务结束后需检查生命周期、所有权与代次。失去前台停止隐私敏感采集；不把麦克风自动恢复与普通会话恢复混为一谈。

## 11. 分阶段与统一回归方法

0.4.0 当时按电源 → 小窗底栏 → 原生方向/通知 → 透明度实现，每项通过后再做下一项。0.5.0 以多设备/后台专项为主，并对受影响的原有远控生命周期做回归。0.5.1 验证了控制队列/输入释放、ADB 写许可和视频追帧的 JVM/回环测试及构建/Lint，未运行设备专项；具体执行范围见 TESTING.md。

0.4.1 为小窗局部外观微调：只编译、静态检查并执行更新后的小窗专项，不重跑未涉及的配对、扫描、文件、麦克风等功能。0.4.0 的完整回归证据保留在 TESTING.md，不能将其写成本次全部重测。

| 原有基本功能及窗口 | `-e windowUi true` | 身份、Shell、文件哈希、扫描、视频、非静音音频、多指、双向剪贴板、旋转、HOME、实体键和小窗往返/关闭 |
| 主界面连接 | `-e mainUiOnly true` | 实际连接操作、地址保存、分级导航和凭据指纹 |
| 实验麦克风 | `-e microphoneOnly true` | 独立 UID 的 MIC/VOICE_COMMUNICATION 录音、路由恢复、停滞停止、并发视频；使用确定性 PCM 源，实际采集授权/停止另行手动验收 |

测试准备：两端安装主控及测试 APK；被控测试探针需录音权限以验证 MIC；主控授予 overlay 和通知权限并确认沉浸说明。真实设备首次使用应按应用内系统授权引导操作，不能用预授权测试代替权限交互验收。

测试有意在专用目标清空 Logcat、生成截图、临时锁定旋转/长按电源行为、启动/停止探针、上传并删除测试文件。小窗专项临时设置长中文设备名，完成后恢复原设备名、窗口位置/大小和不透明度。结束恢复测试临时偏好和系统设置、停止会话和探针；不要对日常工作设备无提示运行这组自动化。设备序列号、IP 和端口不能硬编码到产品逻辑。

实际执行范围与结论写入 [TESTING.md](../TESTING.md)，原始日志和截图按任务归档在被忽略的 `test-results-local/` 中。图像原件生成于主控外部应用目录 `files/ui-smoke/`。正式 APK 不包含这些测试控制入口。

## 12. 实体机补充验收清单

| 场景 | 操作与预期 | 当前证据边界 |
| --- | --- | --- |
| Android 16 → Android 15 | 原有保存身份连接，依次测试电源、触摸、音视频及方向 | 双 Android 16 AVD 不能替代该组合 |
| 厂商电源动作 | 屏幕熄灭后小窗/全屏唤醒，长按设置为助手和电源菜单分别试验，两个组合键 | 音量+ 组合、锁屏密码及助手动作由 ROM 决定 |
| 长时间待机 | 保持远控不操作至目标自然熄屏，再点电源恢复并继续操作 | 本次实现提供电源控制，不承诺阻止目标自然休眠 |
| 多种屏幕 | 刘海、打孔、平板、折叠展开/折叠、正反横竖屏 | 检查系统旋转动画、触控坐标、菜单不越界；方向受系统窗口策略影响 |
| 本地通知栏 | 从主控边缘下滑，再用菜单控制远端面板 | 主控沉浸系统栏仍可被系统手势临时唤出 |
| 小窗 | 最小/最大尺寸、双角斜线手柄拖动、点击不缩放、长设备名省略、四角裁切、等高栏、电源/全屏图标、目标旋转、权限拒绝与通知关闭 | 不应误触远端或重复启动会话；顶部仍可拖动；无关闭小窗的新悬浮菜单 |
| 透明度 | 每种 20/50/100%，小窗与不同应用叠放，重启/覆盖安装 | 不改变窗口命中范围，低透明度下仍有操作入口 |
| USB/OTG | 授权、拒绝、拔线重连、USB 转 TCP | 模拟器只覆盖 USB 协议测试替身；物理链路与供电待测 |
| 无线配对 | 新 PIN、错误 PIN、保存身份重连、随机端口重新扫描 | 新鲜配对需要当次设备产生的端口/PIN，不能复用过期码 |
| 异常网络 | 断网、目标关闭无线调试、主控退出、传输中取消 | 有错误日志，键/触点释放，不继续录音，不把残缺文件当成功 |
| 麦克风 | 两端同意授权后指定应用录音/通话，停止与切换小窗 | Android 14/15 厂商路由与通话品质待测，摄像头仍未实现 |

反馈至少包括主控/被控型号和版本、连接方式、复现步骤、自动旋转开关、透明度值、长按电源设置、日志及画面/声音表现。先在设置 → 诊断保存开启调试日志，再复现并从右上角菜单导出；内部文件为应用 `files/debug.log`，Logcat 标签 `ScrcpyAndroid`。
